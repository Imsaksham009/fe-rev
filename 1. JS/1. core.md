## Part 1: Language Fundamentals

### 1. Primitive vs Reference Types

**What it is:** Primitives (`string`, `number`, `boolean`, `null`, `undefined`, `symbol`, `bigint`) are stored by **value**. Objects (including arrays, functions) are stored by **reference** — the variable holds a pointer to a location in memory.

**Mental model:** A primitive is a sticky note you hand someone a copy of. An object is a house key — hand it over and they get access to the same house, not a copy of it.

```js
let a = 10;
let b = a;
b = 20;
console.log(a); // 10 — untouched, b had its own copy

let obj1 = { val: 10 };
let obj2 = obj1;
obj2.val = 20;
console.log(obj1.val); // 20 — same object, shared reference
```

**Interview line:** "Primitives are copied by value on assignment; objects are copied by reference — the variable just stores a pointer."

> ⚠️ Gotcha: `const obj = {}` still lets you mutate `obj`'s properties. `const` locks the reference, not the contents.

---

### 2. var, let, const

**What it is:**

- `var` — function-scoped, hoisted and pre-initialized as `undefined`, can be redeclared.
- `let` — block-scoped, hoisted but not initialized (TDZ), can be reassigned.
- `const` — block-scoped like `let`, but the binding cannot be reassigned.

**Mental model:** `var` leaks out of `{ }` blocks like water through a cracked cup; `let`/`const` are sealed inside the block they're declared in.

```js
if (true) {
  var x = 1;
  let y = 2;
}
console.log(x); // 1
console.log(y); // ReferenceError — y is block-scoped
```

**Interview line:** "Use `const` by default, `let` when reassignment is needed, avoid `var` — its function-scoping and hoisting behavior causes classic loop/conditional bugs."

---

### 3. Scope

**What it is:** Scope determines where in your code a variable is accessible. JS has global, function, and (since ES6) block scope.

**Mental model:** Nested rooms — code in an inner room can see variables in outer rooms, but outer rooms can't see into inner ones.

```js
let outer = "I'm outside";
function fn() {
  let inner = "I'm inside";
  console.log(outer); // accessible
}
fn();
console.log(inner); // ReferenceError
```

**Interview line:** "Scope is about visibility — where a variable can be referenced — decided by where it's declared."

---

### 4. Lexical Scope

**What it is:** A function's scope is fixed by *where it's written in the source code*, not by where it's later called from.

**Mental model:** Decided at "birth," like a home address fixed the day the house is built — it doesn't change no matter where you travel later.

```js
function outer() {
  let name = "Saksham";
  function inner() {
    console.log(name); // resolved via lexical (write-time) scope
  }
  return inner;
}
outer()(); // "Saksham" — inner "remembers" where it was defined
```

**Interview line:** "Lexical scope means a function resolves variables based on where it was defined — this is exactly what makes closures possible."

---

### 5. Hoisting

**What it is:** Before running code, JS scans the scope and registers declarations upfront — `var` and function declarations hoist with a value/definition; `let`/`const` hoist but stay uninitialized.

**Mental model:** JS takes a table-of-contents pass before reading the book — it notes every name in advance but doesn't fill in values until it reaches that line.

```js
console.log(a); // undefined (var hoisted, not yet assigned)
var a = 5;

console.log(fn()); // works — function declarations hoist fully
function fn() { return "hi"; }

console.log(b); // ReferenceError (TDZ)
let b = 5;
```

**Interview line:** "Hoisting is the creation-phase registration of declarations — `var` gets `undefined`, `let`/`const` sit in the TDZ, function declarations hoist with their full body."

---

### 6. Temporal Dead Zone (TDZ)

**What it is:** The window between entering a scope and the line where a `let`/`const` is actually declared. Accessing it in that window throws a `ReferenceError`.

**Mental model:** A reserved seat for someone who hasn't arrived — the seat exists, but sitting in it early gets you kicked out.

```js
{
  console.log(x); // ReferenceError: Cannot access 'x' before initialization
  let x = 10;
}
```

**Interview line:** "TDZ exists because `let`/`const` are hoisted but not initialized — the engine knows the variable exists but blocks access until its declaration line runs."

---

### 7. Execution Context

**What it is:** The environment JS code runs in — holds variable bindings, the scope chain, and `this`. One Global Execution Context exists, plus a new Function Execution Context per call.

**Mental model:** A fresh notebook page per function call — variables, `this`, and a link to the outer page are written down before any line executes.

```js
// Two phases per context:
// 1. Creation: hoist declarations, build scope chain, bind `this`
// 2. Execution: run code line by line, assign real values
```

**Interview line:** "An execution context has two phases — creation (hoisting, scope, `this` setup) and execution (running the code)."

---

### 8. Call Stack

**What it is:** A LIFO structure tracking function calls. Each call pushes a frame; returning pops it.

**Mental model:** A stack of plates — add to the top on a call, remove from the top on return.

```js
function a() { b(); }
function b() { c(); }
function c() { console.trace(); } // shows a → b → c
a();
```

**Interview line:** "The call stack tracks execution order; `RangeError: Maximum call stack size exceeded` means uncontrolled recursion overflowed it."

---

### 9. Garbage Collection

**What it is:** JS auto-frees memory for objects no longer reachable from the root (global object, active call stack). Main algorithm: **mark-and-sweep**.

**Mental model:** Trace a string from every "root" outward — anything the string never reaches is garbage, swept away.

```js
let obj = { data: "large" };
obj = null; // no references left → eligible for garbage collection
```

**Interview line:** "Mark-and-sweep marks everything reachable from the root and sweeps the rest — unlike simple reference counting, it correctly handles circular references."

---

### 10. Strict Mode

**What it is:** `"use strict"` opts into a restricted JS variant that throws on things that used to fail silently, and disables some unsafe features. Automatically on inside ES6 classes and modules.

**Mental model:** Strict mode is JS with the safety rails up — silent mistakes now throw loudly.

```js
"use strict";
x = 10; // ReferenceError (sloppy mode would silently create a global)
```

**Interview line:** "Strict mode catches silent errors and changes `this` in a plain function call to `undefined` instead of the global object."

---

### 11. this

**What it is:** `this` refers to whichever object is "calling" the function — determined at **call-time** by how the function is invoked, not where it's defined (arrow functions are the exception).

**Mental model:** "Who dialed this phone?" — depends on who made the call, not who wrote the number.

```js
const obj = {
  name: "Saksham",
  greet() { console.log(this.name); }
};
obj.greet(); // "Saksham" — called as obj.greet()

const fn = obj.greet;
fn(); // undefined (strict) — called standalone, lost `this`

const arrow = () => console.log(this); // no own `this`, inherits from enclosing lexical scope
```

**Interview line:** "`this` follows four rules at call-time — default, implicit (`obj.method()`), explicit (`call`/`apply`/`bind`), and `new` — except arrow functions, which take `this` lexically from the surrounding scope."

---

### 12. call, apply, bind

**What it is:** All three explicitly set `this` for a function.

- `call(thisArg, a, b, ...)` — invokes now, args individually.
- `apply(thisArg, [a, b])` — invokes now, args as an array.
- `bind(thisArg, ...)` — returns a **new function**, doesn't invoke immediately.

**Mental model:** `call`/`apply` = "borrow this function and run it right now under a different owner." `bind` = "make a permanent clone that always belongs to this owner."

```js
function greet(greeting) { console.log(`${greeting}, ${this.name}`); }
const person = { name: "Saksham" };

greet.call(person, "Hi");        // "Hi, Saksham"
greet.apply(person, ["Hello"]);  // "Hello, Saksham"
const bound = greet.bind(person);
bound("Hey");                    // "Hey, Saksham" — works anytime later
```

**Interview line:** "`call`/`apply` invoke immediately with a different `this`; `bind` returns a new function with `this` locked in — the classic use is preserving context in event handlers/callbacks."

## Part 2: Objects & Prototypes

### 13. Objects

**What it is:** A collection of key-value pairs (properties); values can be primitives, objects, or functions (methods). The core building block of JS.

**Mental model:** A labeled filing cabinet — each drawer (key) holds a value, looked up by label.

```js
const user = { name: "Saksham", greet() { return `Hi, ${this.name}`; } };
console.log(user.greet()); // "Hi, Saksham"
```

**Interview line:** "Objects are mutable key-value collections — even arrays and functions are objects under the hood."

---

### 14. Prototype

**What it is:** Every object has an internal link (`[[Prototype]]`) to another object it inherits from. This is how JS does inheritance — objects linked to objects, not classical class-based inheritance.

**Mental model:** An "ask my parent" fallback — missing property? Ask the prototype, which asks its own prototype, and so on.

```js
const animal = { eats: true };
const dog = Object.create(animal);
console.log(dog.eats); // true — inherited via prototype
```

**Interview line:** "A property lookup that fails on the object itself falls back to walking its prototype."

---

### 15. Prototype Chain

**What it is:** The chain of `[[Prototype]]` links followed when a property isn't found directly — ending at `Object.prototype`, whose own prototype is `null`.

**Mental model:** Asking upward through an org chart until someone answers or you reach the top (`null`).

```js
const arr = [1, 2, 3];
// arr → Array.prototype → Object.prototype → null
console.log(arr.hasOwnProperty(0)); // true — found on Object.prototype
```

**Interview line:** "Lookup walks up the chain until it finds the property or hits `null` — why every array can call `.map()` without defining it itself."

---

### 16. Constructor Functions

**What it is:** A regular function used with `new` to create objects. `new` creates a fresh object, links its `[[Prototype]]` to `Fn.prototype`, runs the function with `this` bound to that object, and returns it.

**Mental model:** A blueprint/factory — `new` presses the "stamp out a new one" button.

```js
function Person(name) { this.name = name; }
Person.prototype.greet = function() { return `Hi, ${this.name}`; };

const p = new Person("Saksham");
console.log(p.greet()); // "Hi, Saksham"
```

**Interview line:** "`new` creates an empty object, links it to `Fn.prototype`, calls the function with `this` set to it, and returns the object (unless the function explicitly returns another object)."

---

### 17. Classes

**What it is:** ES6 syntax sugar over constructor functions + prototypes — no new inheritance model, just a cleaner syntax for the existing one.

**Mental model:** A nicer dashboard over the same prototype engine.

```js
class Person {
  constructor(name) { this.name = name; }
  greet() { return `Hi, ${this.name}`; } // added to Person.prototype under the hood
}
const p = new Person("Saksham");
console.log(p.greet());
```

**Interview line:** "Class methods live on the prototype, not on each instance — classes are sugar over prototypal inheritance."

> ⚠️ Gotcha: class bodies are always strict mode, and calling a class without `new` throws a `TypeError` — unlike a plain constructor function.

---

### 18. Inheritance

**What it is:** One class/object acquiring properties and methods from another — via `extends`/`super` (classes) or `Object.create`/manual prototype linking (functions).

**Mental model:** A subclass in a family business — gets the parent's tools (`super`) but can override or extend them.

```js
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
}
class Dog extends Animal {
  speak() { return `${super.speak()}, specifically a bark`; }
}
console.log(new Dog("Rex").speak());
```

**Interview line:** "`extends` wires up the prototype chain between child and parent; `super()` calls the parent constructor, `super.method()` calls the parent's version of an overridden method."

---

### 19. `__proto__` vs `prototype`

**What it is:**

- `prototype` — a property that exists **only on functions**; the blueprint object instances get linked to via `new`.
- `__proto__` — a property on **every object** (including functions); the actual live link to what it inherits from. Prefer `Object.getPrototypeOf()` over touching it directly.

**Mental model:** `prototype` is the blueprint sitting in the factory (only functions have factories). `__proto__` is the "made from this blueprint" sticker on every finished product.

```js
function Person() {}
const p = new Person();

console.log(Person.prototype);                  // the blueprint object
console.log(p.__proto__ === Person.prototype);   // true
```

**Interview line:** "`Fn.prototype` is what new instances link to; `instance.__proto__` is the actual link — `instance.__proto__ === Fn.prototype`."

## Part 3: ES6+

### 20. Destructuring

**What it is:** Unpacking array values or object properties into distinct variables in one line, with support for defaults and renaming.

```js
const { name, age = 25 } = { name: "Saksham" };
console.log(name, age); // "Saksham" 25 (default used)

const [first, , third] = [1, 2, 3];
console.log(first, third); // 1 3
```

**Interview line:** "Destructuring extracts by position (arrays) or key (objects) into variables in one expression, with defaults and renaming built in."

---

### 21. Spread

**What it is:** `...` expands an iterable or object into individual elements/properties — used in calls and array/object literals.

```js
const arr2 = [...[1, 2], 3, 4]; // [1, 2, 3, 4]
const obj2 = { ...{ a: 1 }, b: 2 }; // { a: 1, b: 2 } — shallow copy + merge
```

**Interview line:** "Spread expands a collection into individual elements — the standard way to shallow-copy and merge arrays/objects immutably."

---

### 22. Rest

**What it is:** `...` used in a **parameter or destructuring** position to gather *remaining* elements into one array — the opposite direction of spread.

```js
function sum(...nums) { return nums.reduce((a, b) => a + b, 0); }
sum(1, 2, 3); // 6

const [first, ...rest] = [1, 2, 3, 4];
console.log(rest); // [2, 3, 4]
```

**Interview line:** "Rest gathers leftovers into an array; spread expands an array into individual values — same `...` syntax, direction depends on context."

---

### 23. Template Literals

**What it is:** Backtick strings supporting `${}` interpolation and multi-line text without manual concatenation.

```js
const name = "Saksham";
console.log(`Hello, ${name}! 2 + 2 = ${2 + 2}`);
```

**Interview line:** "Template literals allow expression interpolation and multi-line strings, replacing `+` concatenation."

---

### 24. Default Parameters

**What it is:** A fallback value used only when the caller passes `undefined` or omits the argument entirely.

```js
function greet(name = "stranger") { return `Hi, ${name}`; }
greet();          // "Hi, stranger"
greet(undefined); // "Hi, stranger"
greet(null);      // "Hi, null" — null is NOT treated as missing
```

**Interview line:** "Defaults trigger only on `undefined`, never on `null`, `0`, or `''` — a classic gotcha."

---

### 25. Optional Chaining

**What it is:** `?.` short-circuits to `undefined` instead of throwing when accessing a property/method on `null`/`undefined`.

```js
const user = { address: null };
console.log(user.address?.city);   // undefined, no error
console.log(user.getData?.());     // calls only if getData exists
```

**Interview line:** "`?.` stops and returns `undefined` the moment it hits `null`/`undefined`, replacing manual `&&` chains."

---

### 26. Nullish Coalescing

**What it is:** `??` returns the right-hand value only when the left is `null`/`undefined` — unlike `||`, which also falls through on any falsy value.

```js
const count = 0;
console.log(count || 10); // 10 — wrong! 0 is falsy
console.log(count ?? 10); // 0 — correct, 0 isn't nullish
```

**Interview line:** "`??` treats only `null`/`undefined` as missing; use it over `||` whenever `0`, `''`, or `false` are valid values."

---

### 27. Modules

**What it is:** ES Modules (`import`/`export`) split code across files with explicit, statically-analyzable dependencies — unlike Node's older CommonJS (`require`/`module.exports`), which resolves at runtime.

```js
// math.js
export const add = (a, b) => a + b;
export default function multiply(a, b) { return a * b; }

// app.js
import multiply, { add } from './math.js';
```

**Interview line:** "ES Modules resolve imports statically (enabling tree-shaking) and always run in strict mode, unlike CommonJS's dynamic runtime `require`."

---

### 28. Map

**What it is:** A key-value collection where keys can be **any type**, insertion order is preserved, and `.size` gives the count directly.

```js
const map = new Map();
const objKey = {};
map.set(objKey, "value").set("str", 1);
console.log(map.get(objKey)); // "value"
console.log(map.size);        // 2
```

**Interview line:** "Reach for `Map` over a plain object when keys aren't strings, order matters, or you need frequent add/remove with a reliable `.size`."

---

### 29. Set

**What it is:** A collection of **unique** values of any type, with insertion order preserved.

```js
console.log([...new Set([1, 1, 2, 3])]); // [1, 2, 3] — one-line dedupe
```

**Interview line:** "`Set` stores only unique values — `[...new Set(arr)]` is the go-to one-liner to dedupe an array."

---

### 30. Iterators

**What it is:** An object implementing the iterator protocol — a `.next()` returning `{ value, done }`. Arrays, Strings, Maps, and Sets are iterable via `Symbol.iterator`.

```js
const it = [1, 2][Symbol.iterator]();
console.log(it.next()); // { value: 1, done: false }
console.log(it.next()); // { value: 2, done: false }
console.log(it.next()); // { value: undefined, done: true }
```

**Interview line:** "An iterable exposes `Symbol.iterator`, which returns an iterator — `.next()` calls on it are what `for...of` drives under the hood."

---

### 31. Generators

**What it is:** Functions declared with `function*` that pause/resume execution via `yield`. Calling one returns an iterator you drive with `.next()` — the body doesn't run until then.

**Mental model:** A function with a bookmark — `yield` saves your place, `.next()` resumes from there.

```js
function* counter() {
  yield 1;
  yield 2;
  return 3;
}
const gen = counter();
console.log(gen.next()); // { value: 1, done: false }
console.log(gen.next()); // { value: 2, done: false }
console.log(gen.next()); // { value: 3, done: true }
```

**Interview line:** "Generators produce values lazily via `yield`, pausing between calls — useful for infinite sequences or custom iteration logic."

---

### 32. Symbols

**What it is:** A primitive that creates **guaranteed-unique** values, mainly used as non-colliding object keys (e.g. `Symbol.iterator` for custom iteration without clashing with a real `iterator` property).

```js
const id1 = Symbol("id");
const id2 = Symbol("id");
console.log(id1 === id2); // false — always unique, even with the same description
```

**Interview line:** "Every `Symbol()` call is unique — used for hidden, non-colliding metadata keys, including the well-known symbols that hook into language behavior."

## Part 4: Functions

### 33. First-Class Functions

**What it is:** Functions are values in JS — assignable to variables, passable as arguments, returnable from other functions, storable in data structures.

```js
const greet = function() { return "hi"; };  // assigned to a variable
function callIt(fn) { return fn(); }         // passed as an argument
function makeGreeter() { return () => "hi"; } // returned from a function
```

**Interview line:** "Functions being first-class is *why* higher-order functions, callbacks, and closures are all possible."

---

### 34. Higher-Order Functions

**What it is:** A function that takes another function as an argument, returns one, or both. `.map()`, `.filter()`, `.reduce()` are the built-in examples.

```js
function withLogging(fn) {
  return function(...args) {
    console.log("calling with", args);
    return fn(...args);
  };
}
const loggedAdd = withLogging((a, b) => a + b);
loggedAdd(2, 3); // logs, then returns 5
```

**Interview line:** "A higher-order function operates on functions — accepting or returning them — powering `.map`/`.filter` and decorator-style patterns."

---

### 35. Closures

**What it is:** A function keeps access to variables from its lexical scope even after the outer function has finished running.

**Mental model:** A backpack — when a function is created, it packs references to its surrounding variables and carries that backpack wherever it's called later, even after the place it was created is gone.

```js
function makeCounter() {
  let count = 0;
  return function() {
    count++;
    return count;
  };
}
const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2 — count persisted between calls
```

**Interview line:** "A closure is a function plus a live reference to its surrounding scope — the variables survive because the returned function keeps a live link, not a snapshot."

> ⚠️ Gotcha (classic loop question):
>
> ```js
> for (var i = 0; i < 3; i++) {
>   setTimeout(() => console.log(i), 0); // 3, 3, 3 — one shared `i`
> }
> for (let j = 0; j < 3; j++) {
>   setTimeout(() => console.log(j), 0); // 0, 1, 2 — fresh binding per iteration
> }
> ```
>
> `var` is function-scoped, so every callback closes over the *same* `i`. `let` creates a new binding each iteration.

---

### 36. IIFE (Immediately Invoked Function Expression)

**What it is:** A function defined and executed immediately, historically used to create a private scope and avoid polluting the global namespace.

```js
(function() {
  const privateVar = "hidden";
  console.log(privateVar);
})(); // runs immediately, privateVar isn't accessible outside
```

**Interview line:** "IIFEs create an isolated scope on the spot — mostly superseded today by ES modules and block scoping, but still common in bundler output and the module pattern."

---

### 37. Pure Functions

**What it is:** A function that (1) always returns the same output for the same input, and (2) has no side effects.

```js
// Pure
function add(a, b) { return a + b; }

// Impure — mutates external state
let total = 0;
function addToTotal(x) { total += x; return total; }
```

**Interview line:** "Pure functions are deterministic and side-effect-free — easier to test, memoize, and reason about, which is why React wants pure render/reducer functions."

---

### 38. Function Composition

**What it is:** Combining small functions so the output of one feeds into the next.

**Mental model:** An assembly line — input passes through station A, its output feeds station B, and so on.

```js
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x);

const double = x => x * 2;
const addOne = x => x + 1;

const doubleThenAddOne = compose(addOne, double);
console.log(doubleThenAddOne(5)); // double(5)=10, addOne(10)=11
```

**Interview line:** "Composition chains small, pure functions — `compose` applies right-to-left, `pipe` applies left-to-right — the core idea behind Redux/Express middleware chains."
